# AGENTS.md

## Project Overview

B站直播点歌助手 — listens to Bilibili live room danmaku, parses song requests, and switches songs in *Hatsune Miku Project DIVA Mega Mix Plus* by writing to game memory via `pymem`.

**Windows-only.** Memory injection (`song_select.py`) targets `DivaMegaMix.exe` and requires the game to be running. Hotkey listener (`keyboard` lib) needs administrator privileges.

## Developer Commands

```bash
# Install dependencies (uses uv — must be installed separately from https://github.com/astral-sh/uv)
uv sync

# Run the app
uv run python -m diva_live_helper.main
# or via declared script entry point:
uv run diva-live-helper

# Rebuild the local structured song database (manual, run whenever songs/mods change)
uv run update_db
uv run update_db --mods-dir "D:\path\to\game\mods"  # override mods dir

# Build static public Chinese-name database site
uv run build-zh-site
uv run build-zh-site --output-dir docs --repo-url https://github.com/OWNER/REPO

# Add a dependency
uv add <package>
```

No test suite exists yet. `uv run pytest` would run pytest if tests are added under `tests/`.

## Package Layout

```
src/diva_live_helper/
  main.py          # DivaLiveHelper orchestrator + entry point
  config.py        # Config dataclass — loads/saves config.json; all fields have defaults
  danmaku.py       # blivedm BLiveClient wrapper; danmaku callback is async
  song_search.py   # Multi-language fuzzy search; loads Data/song_db.json at runtime
  song_db.py       # Structured song DB model (SongDatabase) + Chinese name DB (ChineseNameDatabase)
  song_select.py   # pymem: writes song ID + sort/diff offsets to game memory
  queue.py         # deque-based SongQueue; carries difficulty metadata; history in memory only
  hotkey.py        # keyboard lib in a daemon thread
  llm_intent.py    # Optional OpenAI-compatible LLM intent parsing (async); returns song_name/author/difficulty
  translator.py    # VocaDB API client (legacy; VocaDB does not reliably carry Chinese names)
  tools/
    update_db.py   # CLI tool: scans pv_db + mods → builds Data/song_db.json + Data/song_name_zh.json
    build_zh_site.py # CLI tool: generates static public Chinese-name database site under docs/
    translate.py   # CLI tool: queries VocaDB for Chinese names (legacy, limited usefulness)
```

`fast_jump_en.py` at repo root is the original monolithic script this project was refactored from — treat it as legacy/reference only.

## Required Config (`config.json`)

Copy from `config.example.json`. The only required fields for startup are `room_id` (Bilibili live room ID) and `hotkey`. Everything else has defaults.

Key non-obvious fields:
- `mods_dir` — absolute path to game's `mods/` folder; each mod must have `rom/mod_pv_db.txt`
- `http_proxy` — used by the LLM client (httpx proxy)
- `llm_enabled` — enables semantic danmaku parsing; falls back to prefix match only when disabled. `llm_api_key` is optional so local OpenAI-compatible models can run without a key.
- `llm_base_url` — OpenAI-compatible; default is DeepSeek. See config.py comments for Qwen/GLM/OpenAI URLs
- `default_search_difficulty` — difficulty tier used for star-rating filter (`"extreme"` by default); options: `"easy"` / `"normal"` / `"hard"` / `"extreme"` / `"exextreme"`
- `difficulty_tolerance` — ±tolerance for star-rating filter (default `0.5`)

## Data Files (`Data/`)

Files required at startup:
- `song_db.json` — **primary structured song DB** generated by `update_db`; keyed by `pv_id` string; contains name/name_en/aliases/authors/difficulty/source; does **not** contain Chinese names
- `song_name_zh.json` — **independent Chinese name DB**; version 3 stores one `entries` object keyed by original song name. Each entry contains `name_zh` plus audit fields (`status`/`source`/`name_en`/`author`/`candidate`/`evidence`).
- `AnotherSongName.json` — legacy alias map `{ alias: canonical_name }`; imported into `song_db.json` aliases on `update_db`
- `HanziKanjiDict.txt` — hanzi→kanji conversion for cross-script search
- `pv_db.txt` — base game song DB (raw, read only by `update_db`)

Generated public site:
- `docs/` — static GitHub Pages-compatible Chinese-name database browser generated by `build-zh-site`; contains `index.html`, frontend assets, and `docs/data/` copies of `song_db.json`, `song_name_zh.json`, `song_name_zh.audit.tsv`, and `manifest.json`.

DLC songs are **not** read from `mdata_pv_db.txt`. They come from mod packs under `mods_dir`.

Legacy files (no longer actively used at runtime):
- `mdata_pv_db.txt` — old DLC DB; superseded by mod packs
- `song_name_cache.json` — old `{ja_name: zh_name}` cache; migrated to `song_name_zh.json` on next `update_db` run

## Architecture Notes

### Danmaku → Song Request Flow
1. `blivedm` delivers danmaku via async callback `_on_danmaku`
2. If prefix matches (`点歌 <name>`) → parse immediately, optionally strip trailing difficulty keyword (e.g. `ex`, `7星`), skip LLM
3. Otherwise, if LLM is enabled → `asyncio.create_task` for async LLM call; LLM returns `song_name`, `author`, `difficulty`
4. `SongSearcher.search()` / `search_by_author()` runs multi-pass lookup with optional star-rating filter
5. First result is added to `SongQueue` with difficulty metadata; duplicates rejected by default
6. Hotkey press → dequeue next song, call `SongSelector.change_song(pv_id)`

### Search Pass Order (`SongSearcher.search`)
1. Japanese/original name (fuzzy)
2. Chinese name (fuzzy, from `song_name_zh.json`)
3. Hanzi→kanji conversion → Japanese name
4. Alias index (`alias_to_ids`, built from `song_db.json` aliases + legacy `AnotherSongName.json`)
5. English name (fuzzy)

Optional star-rating filter applied after candidates are collected, using `config.default_search_difficulty` tier.

### Database Architecture
- **`song_db.json`** — build artifact generated by `update_db`; contains names, aliases, authors, difficulty. Shareable across users (pvid is stable). Not hand-edited normally.
- **`song_name_zh.json`** — standalone shareable Chinese name database keyed by the original `song_db.json` `name` field. Disk format is version 3 `entries`; runtime code derives a fast `{original_name: name_zh}` index in memory.
- **`docs/` public site** — generated read-only browser/download/contribution portal for the Chinese-name database. Source of truth remains `Data/song_db.json` + `Data/song_name_zh.json`; rerun `uv run build-zh-site` after database changes.
- `update_db` loads existing `song_db.json`, re-scans `pv_db.txt` + all mods, rebuilds aliases, migrates Chinese names, and saves both files.

### Memory Layout (song_select.py)
Game process: `DivaMegaMix.exe`. Key offsets from `base_address`:
- `0x12B6350` — `LastSelectPVIDMem` (song ID)
- `0x12B6354` — `LastSelectSortMem` (sort mode; set to `1` = difficulty)
- `0x12B635C` — `LastSelectDiffMem` (difficulty; set to `19` = ALL)
- `0xCC61098` — `ChangeSongSelect` (set to `5` to trigger switch)
- `0xCC610A0` — `StartChange` (set to `2`)

**Eden offset quirk**: if `LastSelectPVIDMem` reads `0`, adds `0x105F460` to all three `LastSelect*` addresses. This handles the "Eden" game variant.

## Conventions

- Python 3.14+ required (`.python-version` pins to `3.14`)
- `uv` manages the venv at `.venv/`; do not use `pip` directly
- No linter/formatter config exists — no enforced style
- All user-facing strings and comments are in Chinese
- `Config` is a plain `@dataclass`; unknown keys in `config.json` are silently ignored
- `config_file` field is serialized to disk via `asdict()` — don't add sensitive fields to `Config` without excluding them from save
- VocaDB does **not** reliably provide Chinese song names; do not rely on `translator.py` / `diva-translate` for bulk Chinese name population
